# 分阶段开发与验收

当前阶段只完成第 0 步。每阶段完成后再进入下一阶段，未开始项不计为项目能力。

| 阶段 | 工作范围 | 验收方式 |
| --- | --- | --- |
| 0：工程骨架 | 根目录、Maven 父工程、Wrapper、Git 规范、文档 | IDEA 识别父 POM，`validate` 成功 |
| 1：首个运行模块 | 创建应用子模块、确定 Spring Boot 版本、添加健康接口 | 启动日志成功，接口返回 JSON |
| 2：前端初始化 | Vue 工程与统一请求封装 | 页面能展示后端健康接口返回值 |
| 3：用户与应用 | 数据库、注册登录、创建应用、应用列表 | 登录并创建应用，刷新后数据仍在 |
| 4：单文件生成 | 模型适配、SSE、HTML 保存和预览 | 输入需求生成并展示网页 |
| 5：持续修改 | 对话历史、上下文、应用级串行控制、任务状态 | 多轮修改可复现，失败能明确反馈 |
| 6：工程构建与发布 | 多文件、Vue 工程、隔离构建、产物存储与版本 | 生成工程可构建、下载、发布 |
| 7：服务演进 | 用户和截图服务拆分、统一入口、监控与故障恢复 | 验证服务调用与故障场景 |

## 下一次只做什么

在后端父工程下添加 `appforge-app` 子模块，并提供唯一的健康接口。届时一起配置应用端口、上下文路径和具体依赖版本。

当前不部署数据库、消息队列或注册中心，不预设并发量、性能指标或上线能力。只有经过测试的行为才写入成果描述。

## 常见误解

- 父工程校验成功，不表示有可访问的网页。
- 没有启动类是当前阶段的正常状态。
- 只在创建实际模块后才添加 `<module>`，防止 Maven 引用不存在的目录。
- 不需要反复删除总目录来切换工程结构。
